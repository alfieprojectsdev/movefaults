# Stage 4 — disagreement report

Generated by `scripts/stage4_disagreement_report.py` from the stage-3
matches. Grouped by pattern, ordered by how many files each explains.

**A disagreement is not an error to correct automatically.** Three
sources of evidence exist — the header position (measured, ~100 m), the
filename and marker (what somebody typed), and the directory (inference
from how somebody once filed a folder). A conflict says two differ; it
does not say which to believe. The catalog entry itself may be wrong.

## Filename and marker conflicts

`claimed_m` is the distance from the header to the site the *filename*
claims. It is what makes a conflict decidable: a claimed site 240 m away
is inside what a header can be wrong by; one 1,000 km away is not.

## What to do with this

Nothing here should be applied automatically. In rough priority:

1. **Fix the ambiguous catalog codes first.** They account for the
   largest conflict groups and need no per-file decision at all — the
   catalog cannot currently say which monument the code meant.
2. **Then the largest unambiguous filename pattern.**
3. **Patterns where marker and filename agree** — two records against the
   position is the strongest case that the catalog is what needs fixing.
4. **Multi-site directories** — these do not need per-file decisions;
   they need path-derived attribution to stop being trusted for them.

## What this does not establish

* **Not which source is wrong.** Only that they differ.
* **Nothing about files with no conflict.** Agreement between a filename
  and an imprecise position is weak corroboration, not proof.
* **Nothing about the `none` and `ambiguous` verdicts**, which are a
  separate question: those files were never attributed at all.
