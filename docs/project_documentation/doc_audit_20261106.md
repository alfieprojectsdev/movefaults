## What this does not cover

`DEAD` 0 is a result about the 325 references the script flagged, not about
every reference in the repo. Measured on the same commit:

- **Two docs were never read.** `tracked_files` splits `git ls-files` on
  whitespace, so `services/vadase-rt-monitor/docs/Architectural Refactor Plan.md`
  and `tools/drive-archaeologist/docs/Smart USB data ingestion system.md` become
  fragments. `Plan.md` and `system.md` count toward the 191, and reading them
  fails silently. The two real docs hold 23 references that would be flagged.
  Their own headers mark them historical and planning, so all 23 would be DATED
  and `DEAD` stays 0. Splitting `git ls-files -z` on NUL fixes the script, and
  the two docs would then join the live list.
- **A reference passes on its file name alone.** `Path(ref).name in basenames`
  accepted 168 references with a directory part that resolve from neither the
  doc nor the root. 15 of those match no tracked path at any depth. Most name
  something gone on purpose or outside the repo (`src/ingestion/`,
  `carpool-app/render.yaml`, the gitignored `services/vadase-rt-monitor/data/`).
  One may be wrong and was not followed up: `analysis/offsets` in
  `docs/project_documentation/roadmap.md`, where the tracked file is
  `docs/bern52/phivolcs-scripts/event-catalog/offsets`.
- **Only backticked paths are checked.** Relative Markdown links are not. They
  were checked separately across the same live docs: 0 broken.
- **This file adds to the script's counts.** The date in its name keeps it out
  of the live set, but its rows raise the script's historical figure from 26
  docs and 232 references to 27 and about 560.

**Suggested change to `HISTORICAL`, not made here.** Matching on content would
be the robust fix, but a narrow extension of the filename rule covers 18 of the
21:

```python
HISTORICAL = re.compile(
    r"(SESSION_LOG|CR-\d{8}|HANDOVER|_20\d{6}|session_log|RESUME_NEXT"
    r"|\d{4}-\d{2}-\d{2}"                 # chat-notes/2025-10-22_...
    r"|(^|/)plans/|legacy_review/"
    r"|CODE_REVIEW|_audit\.md$|_KICKOFF|IMPLEMENTATION_(PLAN|RECOMMENDATIONS)"
    r"|MIGRATION_RUNBOOK|_results\.md$|patch_plan|_readiness"
    r"|(^|/)tech_spec_|(^|/)adr_|work_instructions_review)", re.I)
```

`MIGRATION_RUNBOOK` in that pattern assumes the T420 migration is finished; drop
it if it is not, because a doc marked dated is no longer checked.

Of the other three, two need their header read, not their name:
`services/vadase-rt-monitor/tree.md` opens with "HISTORICAL DOCUMENT", and
`docs/GPS3_COORDINATION_ONBOARDING.md` with "Superseded in part". A check of the
first lines for those two phrases would catch both, and any future doc marked
the same way. The third, `gfzrnx_vs_teqc_rinex3_evidence.md`, is left out of
the pattern because `_evidence\.md$` would also match
`vadase_threshold_evidence.md`, which is kept current.

The pattern also matches 25 tracked docs that were not flagged on this run,
so it was tested against all of them, not only the 21: the other four
chat-notes (dated in the name), every `adr_*` and `tech_spec_*` under
`documentation_portal/`, `gnss_automation_modules/` and
`pogf_infrastructure/`, `legacy_review/CORS-dashboard_review.md`,
`phref_vs_production_comparison_results.md`, `dislocation_model_results.md`
and `plans/igs-downloader-research.md`. They read as records of a decision or a
result, but whoever changes the pattern should confirm that, because a doc
